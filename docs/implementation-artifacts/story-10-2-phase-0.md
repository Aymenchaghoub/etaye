## Proposed choices for approval

- **Version discovery.** Public, stateless `GET /api/v1/meta` serves `apiVersion`, `minimumClientVersion` and `latestClientVersion`. Use `v1` for the route version and the existing `0.0.1` Web version as the initial configured minimum and latest. The SDK sends `X-Client-Version: web/0.0.1` from the Web package version. Record supported client kinds and syntax in the contract guide. The header carries client metadata and grants no authority. Put enforcement of `426 CLIENT_TOO_OLD` with the first stale-client consumer, story 10.4, ahead of native rollout. This preserves ADR-009 and AT-041-B while keeping AT-039 focused on discovery. The two-version/90-day window remains an assumption under ADR-009.
- **Transport and origins.** Use `VITE_ETAYE_MULTI_CLIENT_TRANSPORT`, default `false`. Off selects the existing same-origin browser cookie behavior through the generated SDK. On selects the transport seam with the same browser adapter. Preserve `X-CSRF-TOKEN` on unsafe requests. Verify both flag states and reject a mixed-credential request through HTTP. The Spring allowlist starts empty, matches complete origins and grants no cross-origin credentials in this slice. Verify the Vite proxy preserves the effective same-origin request for development. Native bearer issuance and device binding are owned by 10.5.
- **Push and PDF.** Use a closed event kind for a generic notification and a no-op adapter. Validate shape before it reaches the port and reject extra fields or arbitrary strings at that boundary. There is no public push endpoint in this story. Keep PDF viewing and delivery with their owning stories and D-28. Verify the dependency graph for C8.
- **Layout and theme.** Include ADR-014’s verified navigation `248`, dialog `560/720`, drawer `480/640` and preview `328` px in the normalized data only. The golden CSS adds the four agreed deltas. The technical smoke page keeps its visible styling and French copy. Application theme initialization and style consumption belong to the first consuming screen, with manual preference under S-35. Typography normalizations, chart-axis correction and component overlays follow their consuming UI work. The 15 added roles remain marked for Figma reconciliation.
