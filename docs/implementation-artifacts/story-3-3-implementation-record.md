## 1. What the story delivers

A read-only view of a patient record's measurements, trend and correction lineage, on the real stack (Spring, PostgreSQL with row-level security, React):

- **Contract first** (commit `7206fa3`, before any application code), all additive within `/api/v1`: optional `recordedAt`, `authorLabel`, `sourceReference` and `revision` on `Measurement`; the `concept` filter and the order, paging and `asOf` rules of `listMeasurements`; the new read `listMeasurementRevisions` (101 operations); the optional `timezone` on the membership `AccessContext` (D-64, UD-71 D1). The README section "Measurements", the BR-009 series and display rule, the data dictionary row, the operation index and the roadmap allocation were written with it, and the Web SDK was regenerated (drift check passes). No required response field was added or relaxed, so the ADR-009 question of the packet (G-17) does not arise.
- **Data.** `V11__measurements.sql`: the immutable `measurement` table (revisions that cite their source revision, a decimal stored with the scale it was entered with and bounded to 12 integer and 6 fractional digits, composite practice and record keys, a supersession key inside the record and lineage, an order guard that makes a correction follow its predecessor and keep its concept and group and forbids recording a measurement before the evidence it cites, forced row-level security, `SELECT` only for the runtime role) and the replacement of the V4 context function so a membership context carries the practice zone. `V12__seed_measurements.sql` (demo package): Claire's six measurements (two blood-pressure readings of two components each, the weight lineage 86.4 kg then 68.4 kg) with the correction reason stored once on the source revision, the third replacement of the reset function with `measurement` in its explicit `TRUNCATE` list, and the restore wrapper that seeds them.
- **API** (`records` module): `listMeasurements` and `listMeasurementRevisions` in `RecordEvidenceController`, `RecordEvidenceService` and the JDBC `MeasurementRepository`. They require the actor's current `CLINICAL_READ` membership in the route practice, resolve the record or measurement inside that practice (a foreign, absent or guessed one is the same 404), answer `Cache-Control: no-store` without an `ETag`, bind the cursor to practice, actor, record, view instant and filters, refuse a future `asOf` with 400, cut every instant to the microsecond, and refuse an empty or oversized `concept`. A lineage longer than 100 revisions drops its oldest, never its newest. Routine reads are not audited (D-62).
- **Web** (`apps/web/src/record`): S-11 as the third tab of the record frame, its period and measure filters (relative periods count back from the view instant in the practice zone, UD-72), series panels, a six-column table in observation order, numbered source markers that open in place, the lineage disclosure, loading, partial failure and 429, empty record, filter without result, the three past-instant states, the truncated-series notice, the incomplete reading, mixed units and long content. A hand-built accessible SVG chart with a text alternative that states every plotted value. The display rule of BR-009 is a set of pure functions (series key = exact concept plus unit, a blood-pressure pair only when both components exist, at most two charts, decimals as stored). The practice zone now comes from the session context instead of the Paris constant for the record screens.
- **Defects of the received CSS fixed** (design review F-1, F-2): numeric cells wrap below 760 px and the three-tab bar wraps below 420 px so the current tab stays visible at 320 px; and the inactive tabs, which the authentication stylesheet had turned blue since story 3.2, keep the secondary ink of the approved specimens.
- **Evidence and CI:** the isolation matrix gains eight measurement cases and the `hidden-measurement` parity group (40 cases), the runtime role catalog, the reset test and the 1.3 context assertions were extended, three API suites and three Web files are required by the workflows, and a real-stack spec exists.

Not delivered, by decision (UD-71): `appendMeasurement`, `correctMeasurement`, I-06 and the capability projection (D-24); the concept and unit catalogue, unit conversion and plausibility limits (D-66); unknown or date-only observed time (D-65). The demo journey of 9.1 is unchanged; the demo README describes the Mesures tab.

## 5. Assumptions, findings and limits

- **Observed time and units.** The observed time is a required instant and nothing is converted (UD-71 C1); two spellings of a unit or a concept are two series, so the failure mode is a split, never a silent merge.
- **Concept codes.** `WEIGHT` and the pair `SYSTOLIC_BLOOD_PRESSURE` and `DIASTOLIC_BLOOD_PRESSURE` sharing a `groupId` are the seeded codes; the client labels those and shows any other code verbatim.
- **`concept=` is refused.** Spring turns an empty repeated parameter into no filter, which would have shown every measurement; the controller reads the raw values and answers 400. Found by the first test run of the exactness case.
- **Zone fallback.** A session context without a zone, or with one the browser does not know, falls back to Paris in the web client; the API always sends the zone of a membership. `src/auth/Invitation.tsx` still formats in Paris time; it is outside the record screens.
- **The version of a measurement** equals its revision number (revisions are immutable), as for assertions in 3.2.
- **Lineage bound.** A lineage longer than 100 revisions lists its newest 100, oldest first; entry does not exist yet, so none can reach the bound.
- **Not run.** The real database-outage spec; HawkScan (no key, D-33, UD-47); Firefox and WebKit; screen readers; 200 % zoom; rendered-pixel contrast beyond axe-core; a hosted CI run (the checks run on the pull request). The partial and full failures, the loading state, mixed units, the incomplete reading, long content and the truncated series could not be induced on the real stack without fault injection or a long fixture: those captures and the smoke cases use the stubbed API. G-16 (M2 budget) and G-15 (the series rule shared with the 5.2 composer) stay To verify.
- **Documentation that follows later.** The architecture views and the root README count operations and built stories; as for 3.2 they are refreshed after the merge.
