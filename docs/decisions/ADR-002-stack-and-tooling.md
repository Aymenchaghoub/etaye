# ADR-002 — Current supported stack and tooling

Status: Proposed. Date: 2026-11-02. Amended 2026-11-19: native app row added by [ADR-010](ADR-010-native-client-react-native-expo.md). Amended 2026-11-20: the UI primitives row is replaced by [ADR-013](ADR-013-web-component-behaviour-layer.md), the React line follows the version pinned in `apps/web` and the SDK 58 React version is verified. Related: AD-1/10, FR-020, ADR-013, ADR-014.

User decisions fix Spring Boot, React TypeScript and PostgreSQL. Current official evidence is recorded in [technology and hosting sources](../operations/technology-and-hosting-sources.md).

| Area | Proposed choice | Alternative and consequence |
|---|---|---|
| JVM | Java 25 LTS, open JDK distribution with published security updates | Java 21 LTS remains credible but gives a shorter runway; do not assume Oracle commercial support terms apply to every distribution |
| Backend | Spring Boot 4.1.2 / Spring MVC / Spring Security / Spring Data JPA; BOM controls compatible dependency versions | Boot 3.5 is an alternative whose support window must be rechecked at setup; WebFlux adds a second concurrency model without measured need |
| Build | Maven wrapper on a supported 3.9 release, chosen and checksum-pinned during setup | Gradle also supported; no user value justifies both |
| Database | PostgreSQL 18.6 for CI/local/demo, provider support verified before provisioning | PostgreSQL 17 remains an acceptable documented fallback if a selected provider lacks 18; keep all environments on the same major |
| Browser app | React 19.3.1 (pinned in `apps/web`, story 10.1), TypeScript strict, Vite 8 supported patch, Node 26 LTS | Next.js/SSR evaluated: public showcase can benefit from static pre-render, but clinician workspace needs no second server runtime; do not adopt an app framework only for a landing page |
| Native app (patient first, ADR-010) | React Native with Expo, TypeScript strict; latest stable line observed 2026-11-19 is Expo SDK 58 with React Native 0.88, exact lock at the spike; `expo-secure-store` for the session secret, `expo-notifications` for push | Capacitor (UD-14) rejected by ADR-010; Flutter and Kotlin Multiplatform rejected. An Expo SDK pins its own React (19.2.x for SDK 56 and 57, 19.3.0 for SDK 58, verified 2026-11-20 in the bundled versions of `expo` 58.0.26) while the web proposal is React 19.3, so no shared package may import React |
| UI primitives | React Aria Components for behaviour and accessibility (dialog, sheet, popover, menu, combobox, calendar, date field) with `@internationalized/date`; the Étaye tokens and `.etaye-*` CSS are the only styling layer; native HTML controls remain for buttons, fields, checkboxes, radios and selects. Base UI is the documented fallback; Radix is not retained. Condition: a spike at the first authorised UI story checks the Sheet component (released 2026-10-08), French labels and date formats, keyboard and screen-reader behaviour, and bundle weight ([ADR-013](ADR-013-web-component-behaviour-layer.md)) | MUI/Ant default themes pull identity away from existing foundations; Radix has no combobox, calendar or drawer (verified 2026-11-20); shadcn source snippets are optional references, not a substitute design system |
| State | Local form/UI state, server-query cache (TanStack Query candidate), URL state for safe filters | Global Redux store not justified; never cache clinical data indefinitely across logout/practice changes |
| Migration | Flyway Community SQL, checksums, validate and clean/upgrade test paths | Liquibase supports declarative migrations but adds format/abstraction without a demonstrated need; paid undo is not the rollback strategy |
| Tests | Boot-managed JUnit generation, Testcontainers PostgreSQL, Vitest supported compatible patch at setup, Testing Library, Playwright; native app: Expo Jest preset, React Native Testing Library and an emulator smoke journey (tool chosen at the spike) | H2 and endpoint mocks cannot establish PostgreSQL isolation, constraints or end-to-end behavior |
| PDF | Apache PDFBox 3 supported patch, server-side layout service and embedded licensed fonts | Chromium HTML-to-PDF simplifies CSS but increases memory/startup cost; OpenHTMLToPDF maintenance and accessibility fit require further evaluation before selecting it |

Primary-source validation establishes support and baseline compatibility, **not a successful project build**. Exact tool patches, plugin compatibility, accessibility behavior and PDF layout remain future setup spikes after authorization. Use BOM/lockfiles; do not force independent Spring component versions. Pin base images by digest at release. No starter was run or generated in this phase.
