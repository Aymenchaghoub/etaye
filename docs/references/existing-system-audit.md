## Rechecked investigation leads

The appointment/model, premature-visibility path, empty-score behavior and normalization-order issue are supported by current static evidence above. Two isolated expression demonstrations were run without executing the legacy app: lowercase `Alice Martin` remains `alice martin` after the name regex; zero contributors with the existing weights produce score 0/low. These are narrowly scoped demonstrations, not legacy test-suite or clinical results.

The transaction-local setting deserves precise wording: `set_config(..., true)` lasts for its transaction. The middleware does not pass one transaction context to route operations; the worker also uses the general Prisma client. Actual impact depends on database roles, RLS installation and runtime transactions, none of which was observed. This establishes an enforcement-design gap, not a demonstrated cross-practice data breach.

## Target context consolidation

Keep the useful journey: patient onboarding → dated observations/labs → AI draft → physician review. Add the missing target boundaries: real appointments; source revisions and citations; independent review/publication; practice-local identity and capability checks; safe files; immutable historical corrections; deterministic demo. No legacy source or data has been copied into the Étaye application, and no target application exists.

## Audit limitations and resumption

This is a feature and architecture assessment, not a penetration test or claim of compliance. Runtime/deployment behavior, transaction role settings, complete route-level audit coverage, external AI retention and actual user experience remain unmeasured. Resume runtime legacy verification only if a specific unanswered planning decision requires it and Aymen authorizes a synthetic isolated environment. The new product need not reproduce legacy defects to establish parity.
