C · Entrée dans un scénario

La feuille de route dit : choisir l'acteur fictif (S-01, I-26), puis se connecter (S-02). Aucune opération d'entrée n'existe dans le contrat.
C1 — Entrée côté client via la connexion existante (recommandé) recommandé
« Ouvrir la démonstration » mène à S-02 avec le scénario retenu comme contexte de présentation ; aucune nouvelle voie d'émission de session, AD-4 préservé, signIn inchangé.
C2 — Opération dédiée d'entrée
Un POST /demo/scenarios/{id}/enter ouvre directement la session de l'acteur. Confort maximal, mais seconde voie de session à sécuriser.

La page I-26 montre la distribution et les limites, pas d'identifiants. Le visiteur doit pourtant entrer comme Nora, Claire ou Mila.

D2 — Indice visible, identifiants dans le README démo (recommandé) recommandé
La page montre l'identifiant et indique où trouver le mot de passe (README du paquet démo) ; la page publique reste sobre.
D3 — Rien d'affiché

E · Avis de réinitialisation / version de fixture

AT-035-B : « les sessions actives reçoivent un avis d'invalidation reset/version ». La réinitialisation ferme les sessions (401 → S-38), mais l'onglet ouvert doit aussi apprendre la nouvelle version du jeu.
E1 — Champ additif sur getApiMeta (recommandé) recommandé
Version du jeu de démonstration dans la réponse meta publique, no-store ; additif donc compatible ADR-009 ; aucun endpoint de plus.
E2 — GET /demo/status public
Point de lecture dédié (état, version, disponibilité). Plus explicite, un endpoint de plus à maintenir.
E3 — Re-listing des scénarios uniquement
Le client relit listDemoScenarios après invalidation. Insuffisant pour un onglet déjà ouvert (à n'utiliser qu'en complément).

F · Modèle opérateur de la réinitialisation

Qui détient OPERATOR_DEMO_RESET en incrément 1 ? La matrice d'accès en fait un accès opérationnel, pas un rôle produit.
F1 — Compte opérateur seedé, réservé au paquet local (recommandé) recommandé
Un compte synthétique dédié, sans aucun accès clinique, utilisable depuis la page I-26 de la démo locale ; identifiants dans le README du paquet.
F2 — CLI compose dédiée
docker compose run reset appelle l'opération avec un jeton opérateur embarqué ; pas d'interface produit du tout.
F3 — Route liée à localhost
L'API n'accepte la réinitialisation que depuis l'hôte local. Simple, mais dépend du déploiement (à revoir pour 10.3).

G · Parcours scripté dans CI

UD-34 : le parcours Playwright scripté est à la fois test et enregistreur vidéo. Le critère de sortie incrément 1 demande son passage dans CI.
G1 — Local en 9.1, CI au jalon M6 (recommandé) recommandé
Exécution locale avec compose + preuve vidéo à la livraison ; l'intégration CI (poids, durée) relève de M6/9.2/10.3 qui possède le critère de sortie.
G2 — CI dès 9.1
Le parcours s'exécute dans GitHub Actions dès cette story (stack compose dans CI, allonge API verify/Web verify).
