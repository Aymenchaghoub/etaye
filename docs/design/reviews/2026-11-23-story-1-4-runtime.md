## Corrections made after the first comparison

The first set of comparisons showed four differences that were fixed in `dd73073` and re-captured (a fifth, found on the I-22 sheets, was fixed in `bedddc7`: the neutral shell overflowed the viewport by its padding, so on tall screens its footer notice sat below the fold): the context label was right-aligned in a single-context header, the fictional-data notice disappeared below 760 CSS px (the header badge is hidden and the specimen moves it to the footer), the read-specific session cards used a brighter text than the reference, and the result sat about 21 px lower than the specimen on mobile.

**Focus ring report (Aymen, 2026-11-23).** Aymen reported a blue outline on a button "without hover, almost everywhere", with a 1024×768 capture of S-36 hidden. That capture is `2026-11-22-story-1-4-variants-background/hidden-1024-clair.png` of the design phase. Its script pressed Tab before every capture to record the "keyboard focus cue" (`verification.json`), so every image shows the keyboard ring. In the running application and on the review page, a mouse-driven walk through the journey (Chromium) leaves no button or link with an outline and no `:focus-visible` element except the sign-in e-mail field, which the shared sign-in focuses on load. The ring appears only after Tab, as the design system requires. Playwright now asserts this on every journey state (`ringOnlyForKeyboard`) and after a mouse return to the panel. The separate captures above keep default and keyboard states apart.
