Quatre mouvements qui portent un état

Maquette jouable de l’étude de mouvement fonctionnel, validée par Aymen le 20 novembre 2026 (ADR-012). Ce n’est ni un composant approuvé ni du code d’application. Elle utilise les vrais tokens, les vraies polices et le vrai signe d’Étaye. Les textes en français sont des propositions. Données synthétiques uniquement. Rien n’est envoyé : le navigateur lit seulement le nom, le type et la taille des fichiers déposés.

Inspiration : les expériences de « Kitchen » (dqnamo), réinterprétées. Aucun code ni aucune image n’en est repris.

Règle de base : un mouvement n’existe que s’il dit quelque chose que l’utilisateur doit savoir (en cours, confirmé, échoué, cible active, suite disponible). Chaque mouvement a un équivalent fixe pour « réduire les animations », et l’état est toujours écrit en toutes lettres.

      Ce qui ne change pas

      Écartés

      • Maintenir pour confirmer : un geste de plus n’explique pas mieux la conséquence, et il exclut le clavier.
      • Cassette, cartes, ticket, tampon, reçu, feuille irisée : décor, pas information.
      • Tout mouvement sur publier, retirer, valider, abandonner.

      Conservé tel quel

      • Confirmations explicites avec la cible et le public nommés.
      • « Pas de lueur, de dégradé ni d’animation gratuite » : la règle reste.
      • Rien n’est affiché comme réussi avant la validation du serveur.

      ### 4.5 Motion and the floating shadow  (existing table kept)
+ | `--duree-trace` | 1200ms | [Proposal] one-shot trace of the sign, S-01 only |

  Only the color transitions of links and buttons and a 0.98 press scale exist in the reference. (kept)
+ **Functional motion.** Motion is allowed only when it carries a state the user
+ needs: pending, confirmed, failed, active drop target, more content available.
+ Each functional motion:
+   1. reuses `--courbe` and the existing durations, except the one logo trace;
+   2. has a static equivalent with the same information under
+      `prefers-reduced-motion: reduce`;
+   3. never replaces text: the state is also written;
+   4. never runs longer than the work it reports, and nothing auto-plays
+      longer than 5 seconds;
+   5. never shows success before the server commit.
+ Patterns: save button states (SP-SAVE), file drop target (I-08), demo
+ preparation trace (S-01), overflow fade for long lists.
+ Not allowed: skeuomorphic scenes, hold-to-confirm gestures, any motion on
+ publish, withdraw, validate or discard.
  No decorative glow, gradient or gratuitous animation. (kept)
