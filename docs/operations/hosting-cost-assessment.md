## Capacity and dependency assessment

Measure Java heap, metaspace, native/thread/database pool and PDF peak RSS together; do not allocate full512MB as heap. Start with bounded thread/pool/task concurrency; p95 warm response and startup/memory evidence decide viability. Sleep means DB-backed jobs resume later rather than vanish; it does not provide an always-on worker. Show a service-warming/unavailable state, bounded retries and deterministic AI fallback only when explicitly labeled as demo response.

Neon1GB DB quota includes schema/history growth; retain bounded synthetic rows and reset fixture version safely. Pool remote connections with TLS and verify RLS transaction context through chosen pooling mode.6h restore window is not a backup strategy: export versioned synthetic fixture plus scheduled encrypted DB/byte backup where necessary, restore-test separately. Object storage needs private ACL, region, durable bytes and explicit guarded download; assess R2 versus Neon object service before selecting adapter. No large binaries in relational free storage by default.

## Update 2026-11-26 (Empirical capacity benchmark & Azure for Students comparison)

Clean isolated cgroup capacity measurements (`--memory-swap == --memory`) and read-only Azure CLI inspection added the following verified facts (full methodology and tables in [deployment-readiness.md](deployment-readiness.md)):

1. **JVM container footprint (`512 MiB` vs `1–2 GiB`)**: Inside a real `512 MiB` / `0.25 vCPU` cgroup, default JVM peaked at `276.4 MB` (`61.03 s` startup, `21.5 RPS`), while tuning (`-Xmx192m -XX:MaxMetaspaceSize=96m -Xss256k -XX:+UseSerialGC -XX:TieredStopAtLevel=1`, Hikari max `5`) reduced peak cgroup memory to **`218.6 MB`** (`36.47 s` startup, `32.5 RPS`, `0` OOM kills or HTTP errors across 190 load probes). Under `0.5 vCPU / 1 GiB` tuned, cold startup dropped to `27.95 s` (`262.9 MB` peak, `43.1 RPS`). Memory is therefore manageable inside `512 MiB` for Sprint 3 scope (before PDFBox generation), making **CPU quota** the main cold-start bottleneck on Render Free (~`0.1` CPU).
2. **Azure for Students (`USD 100`, expires `2027-11-26`, `USD 0` spent)**: Subscription policy `sys.regionrestriction` allows only five European regions (`norwayeast`, `belgiumcentral`, `polandcentral`, `italynorth`, `germanywestcentral`) and marks all `Standard_B*` burstable VMs `NotAvailableForSubscription`. Always-on `D2s v4`/`D2as v4` VMs (`~75.34 EUR/month`) would drain credits in ~5 weeks, and Azure PostgreSQL Flexible Server `B1ms` runs `~13.07 EUR/month` + storage after the 12-month student grant.
3. **Owner's provisional candidate:** Azure Container Apps Consumption (one app/revision with Nginx proxy plus loopback API), Neon Free PostgreSQL 18, and exact public GHCR digests when separately authorized. Free Render + Neon remains the fallback. Azure VMs are excluded under the student account restrictions and zero-spend target.

### Future authentication and cutover

A future authorized deployment workflow would use GitHub OIDC with a configured Entra federation restricted to this repository's protected deployment environment, an identity limited to the target Container App resources, and `id-token: write` on that trusted deployment job only. OIDC to Azure and publisher authentication to GHCR are separate permissions. Validate any login helper against the selected-actions allowlist before proposing a dedicated change. [Microsoft GitHub OIDC instructions](https://learn.microsoft.com/en-us/azure/developer/github/connect-from-azure-openid-connect)

Before any cutover, verify the release manifest and attestations and preserve previous compatible digests plus a pre-change logical dump. Rehearse roles, Flyway checksums, schema migration and synthetic restore on an isolated target. Apply forward-only migrations once with dedicated credentials, validate, start the single same-origin revision, and gate traffic on readiness and synthetic authorization checks. Use traffic shift to the previous digest if its schema is compatible. If schema recovery is necessary, restore the pre-release dump into a separate database, verify isolation and file references, then switch intentionally. Remote registry publication, identity setup, provider changes, migrations and deployment each require authorization. [Deployment and rollback detail](deployment-readiness.md#8-rollback-runbook)
