# Data dictionary

Status: Proposed. 2026-11-02. `?` means nullable; all other listed fields required except generated timestamps/identifiers supplied server-side. Common UUID/ownership/version rules are in [data model](data-model.md). Fields are conceptual/logical English names, not implemented columns.

| Entity | Responsibility | Required fields / nullable fields (?) | Constraints and lineage |
|---|---|---|---|
| Account | Global authentication identity | id; normalized_email; display_name; password_hash; state; locale; created_at; updated_at; version | Email unique after defined case normalization; password hash never in API/logs. States per BR-005. No clinical practice ownership implied. |
| Session | Global opaque browser session | id_hash; account_id; created_at; last_seen_at; absolute_expires_at; assurance_at | Account 1→0..N sessions; revoke on logout/reset/suspension; never store browser bearer token in localStorage. |
| Practice | Tenant and operational settings | id; display_name; timezone; booking_policy; state; created_at; updated_at; version | IANA timezone required. Booking policy has bounded slot/cutoff/horizon values, proposed defaults reviewed before build. |
| Membership | Account access to one practice | id; practice_id; account_id; state; capabilities; created_at; updated_at; version | Unique(account_id,practice_id); state ACTIVE/SUSPENDED. Capability changes audited; final active administrator protected by serialized invariant. |
| Practitioner | Professional profile in practice | id; practice_id; membership_id; display_name; active; version | Unique membership profile; membership account is responsible actor. Same person may have separate profiles in two practices. |
| Patient | Practice-local patient identity | id; practice_id; first_name; last_name; date_of_birth; contact_email?; phone?; version | Not globally matched; contact email is not globally unique or identity authority. Duplicate candidate handling is human, no merge now. |
| PatientRecord | Longitudinal record boundary | id; practice_id; patient_id; record_revision; created_at; updated_at; version | One record per local Patient; unique(practice_id,patient_id). No account credentials stored on clinical identity. |
| PortalLink | Verified self-access link | id; practice_id; record_id; account_id; verified_by; verified_at; state; version | Account 1→0..N record links; local record can have 0..1 active adult self-link [ASSUMPTION]. No guardian/delegate roles. Revoke without deleting history. |
| Invitation | Expiring intended grant | id; practice_id; purpose; intended_recipient; token_digest; expires_at; state; issuer_id; accepted_at?; version | Purpose TEAM_MEMBERSHIP/PATIENT_PORTAL; proposed capabilities or record target explicit. Raw token never persisted; atomic one-use acceptance; resend creates new ID. |
| AvailabilityRule | Practitioner working interval | id; practice_id; practitioner_id; timezone; weekday; local_start; local_end; valid_from; valid_until?; version | Bounded recurring rule, dates inclusive policy specified. Local recurrence resolves DST explicitly when creating offered slots. |
| AvailabilityException | Dated available or blocked interval | id; practice_id; practitioner_id; start_at; end_at; kind; reason; version | start<end; kind AVAILABLE/BLOCKED. Changes serialize with booking and expose impacted commitments. |
| Appointment | Actual scheduling aggregate | id; practice_id; record_id; practitioner_id; start_at; end_at; timezone; state; scheduling_reason?; cancellation_reason?; version | Half-open ranges. Exclusion constraints for practitioner and local record over BOOKED/CHECKED_IN intervals. State transitions BR-006. No consultation invented. |
| VisitPreparation | Patient-authored visit input | id; practice_id; record_id; appointment_id; author_account_id; submitted_at; concerns; questions; reported_treatments?; version | Same-record appointment; patient-reported provenance immutable. Eligible edits before encounter starts; later additions become new dated submissions. |
| Consultation | Clinical encounter | id; practice_id; record_id; practitioner_id; appointment_id?; encounter_at; state; structured_notes; version | Appointment optional, same record/practitioner/practice; one active encounter link per appointment. Completion independent from report/validation/publication. |
| ClinicalAssertion | History/allergy/reported-treatment assertion | id; practice_id; record_id; category; assertion_kind; text?; source_revision_id; version | Kinds PRESENT/EXPLICITLY_ABSENT/UNKNOWN/NOT_ASKED. Unknown has no invented negative. No prescription domain. |
| SourceRevision | Immutable evidence and correction lineage | id; practice_id; record_id; source_type; source_entity_id; source_version; event_at?; event_date_precision; recorded_at; author_id?; reporter_label; supersedes_id?; correction_reason? | Types PATIENT_REPORTED/PRACTITIONER_OBSERVED/DOCUMENT_REPORTED. Explicit unknown event date; locator metadata and immutable payload checksum. Same record lineage; correction requires reason. |
| Measurement | Quantitative observation | id; practice_id; record_id; concept; value_decimal; unit; observed_at; source_revision_id; supersedes_id? | Decimal numeric storage; original value/unit retained. | LabResult | Manual laboratory observation | id; practice_id; record_id; analyte; value_kind; numeric_value?; qualitative_value?; comparator?; unit?; lower_bound?; upper_bound?; interval_text?; interval_source?; specimen_at?; result_at?; source_revision_id; supersedes_id? | Exactly one numeric/qualitative value; comparator allowed for numeric. Bounds/units only when supplied; low≤high if both. Source interval context retained, no clinical thresholds invented. |
| RecordDocument | Uploaded document metadata | id; practice_id; record_id; title; original_filename; media_type; byte_size; sha256; storage_key; inspection_state; uploaded_by; uploaded_at; source_revision_id; version | Metadata practice-owned; opaque non-public storage key. | ClinicalDocument | Logical report/brief/explanation identity | id; practice_id; record_id; consultation_id?; purpose; created_at | Purpose CLINICIAN_BRIEF/CONSULTATION_REPORT/PATIENT_EXPLANATION. 1→1..N versions. Brief ineligible for patient publication. |

| StatementCitation | Statement support relation | id; practice_id; document_version_id; statement_id; source_revision_id; locator; excerpt; support_review | Version 1→0..N citations; one statement may have several. | ReviewEvent | Human review event | id; practice_id; document_version_id; reviewer_id; event; at; reason?; reviewed_source_hash | STARTED/CHANGES_REQUESTED/VALIDATED events; actor has current capability. Events append-only; not mutable second business status. |
| Publication | Audience-specific immutable version grant | id; practice_id; record_id; document_version_id; audience_link_id; state; published_by; published_at; replaces_id?; withdrawn_at?; reason_internal?; patient_notice?; version | One active PUBLISHED projection per clinical_document+audience; atomic replacement. Eligible VALIDATED CURRENT version only. Patient sees curated content, no internal withdrawal reason. |
| PublicationSourceGrant | Curated patient evidence projection | id; practice_id; publication_id; source_revision_id; public_label; approved_excerpt; attachment_document_id? | Only explicitly approved excerpts/attachments. Parent grant authorization required on every read; withdrawal/replacement revokes future access. |
| ProcessingTask | Leased AI/scan/export processing | id; practice_id; record_id?; purpose; status; requestor_id; idempotency_key; input_snapshot; target_version_id?; attempt; lease_token?; lease_expires_at?; queued_at; started_at?; finished_at?; failure_code? | Statuses QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED. Lease fencing prevents late commits. Unique request scope/key/body hash; limited retries, per-practice quota. No output is automatically reviewed. |
| ExportArtifact | Immutable generated PDF snapshot | id; practice_id; record_id; source_version_id; publication_id?; template_id; template_version; sha256; storage_key; created_at; task_id | Patient retrieval requires still-current publication; clinician retrieval current clinical grant. | OutboxEvent | After-commit integration/notification event | id; practice_id; event_type; resource_id; resource_version; dedupe_key; safe_payload; created_at; delivery_state; attempt; next_attempt_at | Written in same DB transaction as domain/audit change. | AuditEvent | Scoped append-only accountability | id; practice_id?; actor_account_id?; service_identity?; event_type; resource_type; resource_id?; resource_version?; outcome; occurred_at; correlation_id; safe_metadata | No clinical body/prompt/token. | IdempotencyReceipt | Retry outcome without duplicate business effects | id; practice_id?; actor_id; operation; key_digest; body_hash; response_resource; outcome; expires_at | Unique actor+practice+operation+key. Same key different body→409. Proposed 24h retention; sensitive response body not cached indefinitely. |

## Shared value definitions

- UUID is opaque, never a permission. Common practice-scoped foreign keys include practice_id. Immutable resource revision IDs are distinct from optimistic-lock version counters.
- EventDate contains nullable instant/date, precision INSTANT/DATE/UNKNOWN, recordedAt and original timezone when provided; UNKNOWN cannot carry a fabricated instant.
- Decimal values use a finite decimal string in JSON, numeric database storage, bounded precision specified per concept; units are explicit original codes/labels. No universal medical validity ranges are invented.
- SourceSnapshot lists sourceRevisionId, resource version, inclusion/exclusion reason, record revision watermark and hash. Relevance includes newly added source categories, not only edited cited sources.
- Review validation requires exact sourceSnapshot hash, validator identity/date, support disposition and no unresolved required-field errors.
- PatientProjection includes only approved body/metadata/citation excerpts/attachment grants. Internal notes/generated alternatives/hidden source locators never leak by serialization.
- Public demonstration aliases such as PRA-A are design identifiers, not API UUID examples. Map them deterministically at future fixture setup and retain mapping for tests.
