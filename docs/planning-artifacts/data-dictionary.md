# Data dictionary

Status: Proposed. 2026-11-02. `?` means nullable; all other listed fields required except generated timestamps/identifiers supplied server-side. Common UUID/ownership/version rules are in [data model](data-model.md). Fields are conceptual/logical English names, not implemented columns.

| Entity | Responsibility | Required fields / nullable fields (?) | Constraints and lineage |
|---|---|---|---|
| Account | Global authentication identity | id; normalized_email; display_name; password_hash; state; locale; created_at; updated_at; version | Email unique after defined case normalization; password hash never in API/logs. States per BR-005. No clinical practice ownership implied. |
| Session | Global opaque browser session | id_hash; account_id; created_at; last_seen_at; absolute_expires_at; assurance_at | Account 1→0..N sessions; revoke on logout/reset/suspension; never store browser bearer token in localStorage. |
| Practice | Tenant and operational settings | id; display_name; timezone; booking_policy; state; created_at; updated_at; version | IANA timezone required. Booking policy has bounded slot/cutoff/horizon values, proposed defaults reviewed before build. |
| Membership | Account access to one practice | id; practice_id; account_id; state; capabilities; created_at; updated_at; version | Unique(account_id,practice_id); state ACTIVE/SUSPENDED. Capability changes audited; final active administrator protected by serialized invariant. |
| Practitioner | Professional profile in practice | id; practice_id; membership_id; display_name; active; version | Unique membership profile; membership account is responsible actor. Same person may have separate profiles in two practices. |
| Patient | Practice-local patient identity | id; practice_id; first_name; last_name; date_of_birth; contact_email?; phone?; version | Not globally matched; contact email is not globally unique or identity authority. Duplicate candidate handling is human, no merge now. PD-001 scheduling registration creates only this identity and an empty PatientRecord; its response projection grants no clinical access. |
| PatientRecord | Longitudinal record boundary | id; practice_id; patient_id; record_revision; created_at; updated_at; version | One record per local Patient; unique(practice_id,patient_id). No account credentials stored on clinical identity. |
| PortalLink | Verified self-access link | id; practice_id; record_id; account_id; verified_by; verified_at; state; version | Account 1→0..N record links; local record can have 0..1 active adult self-link [ASSUMPTION]. No guardian/delegate roles. Revoke without deleting history. |
| Invitation | Expiring intended grant | id; practice_id; purpose; intended_recipient; token_digest; expires_at; state; issuer_id; accepted_at?; version | Purpose TEAM_MEMBERSHIP/PATIENT_PORTAL; proposed capabilities or record target explicit. Raw token never persisted; atomic one-use acceptance; resend creates new ID. |
| AvailabilityRule | Practitioner working interval | id; practice_id; practitioner_id; timezone; weekday; local_start; local_end; valid_from; valid_until?; version | Bounded recurring rule, dates inclusive policy specified. Local recurrence resolves DST explicitly when creating offered slots. |
| AvailabilityException | Dated available or blocked interval | id; practice_id; practitioner_id; start_at; end_at; kind; reason; version | start<end; kind AVAILABLE/BLOCKED. Changes serialize with booking and expose impacted commitments. |
| Appointment | Actual scheduling aggregate | id; practice_id; record_id; practitioner_id; start_at; end_at; timezone; state; scheduling_reason?; cancellation_reason?; version | Half-open ranges. Exclusion constraints for practitioner and local record over BOOKED/CHECKED_IN intervals. State transitions BR-006. No consultation invented. |
| VisitPreparation | Patient-authored visit input | id; practice_id; record_id; appointment_id; author_account_id; submitted_at; concerns; questions; reported_treatments?; acknowledged_by?; acknowledged_at?; version | Same-record appointment; patient-reported provenance immutable. Eligible edits before encounter starts; later additions become new dated submissions. The practitioner acknowledgement (UD-18) is set once per submission, never changes authorship or content, and a later submission needs its own. |
| Consultation | Clinical encounter | id; practice_id; record_id; practitioner_id; appointment_id?; encounter_at; state; structured_notes; version | Appointment optional, same record/practitioner/practice; one active encounter link per appointment. Completion independent from report/validation/publication. |
| ClinicalAssertion | History/allergy/reported-treatment statement | id; practice_id; record_id; category; assertion_kind; text?; event_precision; event_at?; event_date?; event_timezone?; source_revision_id?; recorded_at; lineage_id; revision; supersedes_id?; correction_reason?; created_at | Kinds PRESENT/EXPLICITLY_ABSENT/UNKNOWN/NOT_ASKED. One row per statement, never one aggregate row per category. Unknown and not-asked statements have no invented negative and may carry no text or source (the only rows without a source revision; PRESENT and EXPLICITLY_ABSENT always cite one); an unknown event date forbids a fabricated instant or date. `recorded_at` is server-provided and decides the `asOf` view. A correction appends a revision of the same lineage and record with its reason (story 3.2 seeds rows and serves reads; entry and correction move to increment 2, D-60). The section state is derived, never stored (BR-008). No prescription domain. |
| SourceRevision | Immutable evidence and correction lineage | id; practice_id; record_id; lineage_id; revision; reference; kind; label; excerpt?; source_type; event_precision; event_at?; event_date?; event_timezone?; recorded_at; author_label; locator?; supersedes_id?; correction_reason?; created_at | Types PATIENT_REPORTED/PRACTITIONER_OBSERVED/DOCUMENT_REPORTED; kinds are the `SourceKind` values of the contract. `lineage_id` and `revision` realize the logical `source_entity_id` and `source_version`. Unique (record, lineage, revision); a superseding revision stays in the same record and lineage, has a higher revision, and requires its reason; an original has none. Explicit unknown event date; `label` and `excerpt` are plain text, the excerpt is the dated text stored with the revision. The runtime role has `SELECT` only on the rows (story 3.2); no update or delete exists. The payload checksum arrives with uploaded documents (3.5). |
| Measurement | Quantitative observation | id; practice_id; record_id; lineage_id; revision; concept; value_decimal; unit; observed_at; recorded_at; author_label; source_revision_id; group_id?; supersedes_id?; correction_reason?; created_at | Immutable revisions, as for SourceRevision: unique (record, lineage, revision), a superseding revision stays in its record and lineage and requires its reason, an original has none, and a revision is never recorded before the source revision it cites. Decimal numeric storage (up to 12 integer and 6 fractional digits); original value/unit retained and never converted. `observed_at` is always an instant (D-65). BP is two components (systolic and diastolic concepts) sharing a `group_id`, not an ambiguous 134/82 scalar; an incomplete group stays incomplete. Missing is absent, not zero. The runtime role has `SELECT` only (story 3.3); entry and correction move to increment 2 (D-24). |
| LabResult | Manual laboratory observation | id; practice_id; record_id; analyte; value_kind; numeric_value?; qualitative_value?; comparator?; unit?; lower_bound?; upper_bound?; interval_text?; interval_source?; specimen_at?; result_at?; source_revision_id; supersedes_id? | Exactly one numeric/qualitative value; comparator allowed for numeric. Bounds/units only when supplied; low≤high if both. Source interval context retained, no clinical thresholds invented. |
| RecordDocument | Uploaded document metadata | id; practice_id; record_id; title; original_filename; media_type; byte_size; sha256; storage_key; inspection_state; uploaded_by; uploaded_at; source_revision_id; version | Metadata practice-owned; opaque non-public storage key. Inspection QUARANTINED/CLEAN/REJECTED/FAILED, not document review status. Bytes immutable; revision replaces content. |
| ClinicalDocument | Logical report/brief/explanation identity | id; practice_id; record_id; consultation_id?; purpose; created_at | Purpose CLINICIAN_BRIEF/CONSULTATION_REPORT/PATIENT_EXPLANATION. 1→1..N versions. Brief ineligible for patient publication. |
| DocumentVersion | Versioned authored/reviewed content | id; practice_id; record_id; clinical_document_id; version_number; parent_version_id?; business_status; freshness; generated_baseline?; human_content; author_id; created_at; validated_by?; validated_at?; source_snapshot_hash; version | Unique(document_id,version_number). VALIDATED requires validator/time and immutable content. New draft for changes. Separate generation baseline and human revision, exact source manifest. CLINICIAN_BRIEF versions never leave DRAFT (UD-22); their acknowledgement is a ReviewEvent projected as acknowledgedBy/acknowledgedAt for the current version counter. |
| StatementCitation | Statement support relation | id; practice_id; document_version_id; statement_id; source_revision_id; locator; excerpt; support_review; mechanical_check | Version 1→0..N citations; one statement may have several. FK same record/practice; page/section/span locator; source existence does not prove support. Human-reviewed support before validation. mechanical_check is PASS_MECHANICAL, FLAG_VALUE_NOT_FOUND, FLAG_SUPERSEDED, FLAG_NEGATION_MISMATCH or UNVERIFIED (BR-012, UD-31); it is never a score. |
| ReviewEvent | Human review event | id; practice_id; document_version_id; reviewer_id; event; at; reason?; reviewed_source_hash | STARTED/CHANGES_REQUESTED/VALIDATED events for reports and explanations, and ACKNOWLEDGED for CLINICIAN_BRIEF only (UD-22, carrying the version counter and record watermark); actor has current capability. Events append-only; not mutable second business status. |
| Publication | Audience-specific immutable version grant | id; practice_id; record_id; document_version_id; audience_link_id; state; published_by; published_at; replaces_id?; withdrawn_at?; reason_internal?; patient_notice?; version | One active PUBLISHED projection per clinical_document+audience; atomic replacement. Eligible VALIDATED CURRENT version only. Patient sees curated content, no internal withdrawal reason. |
| PublicationSourceGrant | Curated patient evidence projection | id; practice_id; publication_id; source_revision_id; public_label; approved_excerpt; attachment_document_id? | Only explicitly approved excerpts/attachments. Parent grant authorization required on every read; withdrawal/replacement revokes future access. |
| ProcessingTask | Leased AI/scan/export processing | id; practice_id; record_id?; purpose; status; requestor_id; idempotency_key; input_snapshot; target_version_id?; attempt; lease_token?; lease_expires_at?; queued_at; started_at?; finished_at?; failure_code? | Statuses QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED. Lease fencing prevents late commits. Unique request scope/key/body hash; limited retries, per-practice quota. No output is automatically reviewed. |
| ExportArtifact | Immutable generated PDF snapshot | id; practice_id; record_id; source_version_id; publication_id?; template_id; template_version; sha256; storage_key; created_at; task_id | Patient retrieval requires still-current publication; clinician retrieval current clinical grant. No copied sensitive body in logs. Regeneration links exact source/template versions. |
| OutboxEvent | After-commit integration/notification event | id; practice_id; event_type; resource_id; resource_version; dedupe_key; safe_payload; created_at; delivery_state; attempt; next_attempt_at | Written in same DB transaction as domain/audit change. Unique dedupe key; bounded retries; no raw token in logs. Secret link material protected with short retention if delivery needs it. |
| AuditEvent | Scoped append-only accountability | id; practice_id?; actor_account_id?; service_identity?; event_type; resource_type; resource_id?; resource_version?; outcome; occurred_at; correlation_id; safe_metadata | No clinical body/prompt/token. Clinical vs administrative projections; global security events lack practice only when genuinely global. Successful mutation audit committed atomically; denied attempts distinct. |
| IdempotencyReceipt | Retry outcome without duplicate business effects | id; practice_id?; actor_id; operation; key_digest; body_hash; response_resource; outcome; expires_at | Unique actor+practice+operation+key. Same key different body→409. Proposed 24h retention; sensitive response body not cached indefinitely. |
| DeviceRegistration | Native or installed client of an account (proposed with ADR-008; not part of increment 1) | id; account_id; client_kind; platform; push_token?; created_at; last_seen_at; revoked_at? | Account 1→0..N devices; identity-module data with no clinical content; revoked on logout, suspension and password reset; its native session is revoked with it. Push token handled as a secret. |

## Shared value definitions

- UUID is opaque, never a permission. Common practice-scoped foreign keys include practice_id. Immutable resource revision IDs are distinct from optimistic-lock version counters.
- EventDate contains nullable instant/date, precision INSTANT/DATE/UNKNOWN, recordedAt and original timezone when provided; UNKNOWN cannot carry a fabricated instant.
- Decimal values use a finite decimal string in JSON, numeric database storage, bounded precision specified per concept; units are explicit original codes/labels. No universal medical validity ranges are invented.
- SourceSnapshot lists sourceRevisionId, resource version, inclusion/exclusion reason, record revision watermark and hash. Relevance includes newly added source categories, not only edited cited sources.
- Review validation requires exact sourceSnapshot hash, validator identity/date, support disposition and no unresolved required-field errors.
- PatientProjection includes only approved body/metadata/citation excerpts/attachment grants. Internal notes/generated alternatives/hidden source locators never leak by serialization.
- Public demonstration aliases such as PRA-A are design identifiers, not API UUID examples. Map them deterministically at future fixture setup and retain mapping for tests.
