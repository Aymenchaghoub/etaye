## Cross-journey behavior

Lists paginate and expose active filters with a clear reset; empty data and filtered no-results differ. Save indicators describe confirmed persistence. Keep processing, content review, freshness and publication as distinct axes. Navigation/practice change/session expiry must preserve unsaved input only within safe account/practice memory and provide explicit discard/re-authenticate choices. Do not cache clinical bodies in persistent shared-browser storage.

Appointment reasons may be sensitive: scheduler sees only what is necessary for scheduling, never unrelated clinical notes. Patient preparation locks for an active encounter; later additions are new dated submissions. Practitioner acknowledgement does not change original authorship. Exact cutoffs and availability policy defaults are A-07 decisions for design review.

Patient publication is an immutable audience-specific projection. It can include a selected consultation report or a separately reviewed patient explanation, never a clinician brief by re-labeling. A citation for the patient resolves to a permitted published excerpt/attachment; a source ID alone grants nothing. See I-17/I-18 and the publication contract.

## Verification contract

Every journey has a navigable prototype, critical errors and permissions at desktop/tablet/mobile. Functional acceptance and visual review are independent. Implementation acceptance uses real database/API/UI boundaries and deterministic external AI responses, with actual evidence recorded only when executed.
